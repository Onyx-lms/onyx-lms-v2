Verdict — ship with fixes

The security model holds. No cross-tenant read succeeded in 59 attempts, no privilege-escalation write succeeded in 42, and no page in the sweep threw a server error. A complete content lifecycle — institution, programme, course, modules, lessons, question bank, paper, sitting, marking, release, examination, seating, marks, publication — ran end to end through both the API and the screens. The eleven defects are a missing header set, four read endpoints looser than the product's own capability model, a mis-seeded demo account, a dead link, a contrast failure, an inverted date and a learner record naming exams by database ID. None is a breach.

02

Defects

11 confirmed · each traced to source

Every entry was reproduced against the live deployment and then traced to the line responsible. F3 through F6 share one root cause — a POST that asserts a capability sitting directly above a GET that does not — and are best fixed together.

F1 Medium
No security response headers except HSTS
Only Strict-Transport-Security is sent. No CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy or Permissions-Policy — the last of which governs the camera and microphone that proctoring depends on, and the missing frame protection leaves the login and invigilation screens frameable.
Fix apps/web/next.config.js — add a headers() block
F2 Medium
Demo faculty account is seeded as an administrator
faculty@demo.onyx holds role: "admin". The guard is correct — the Meridian faculty control account is properly denied — but ten browser specs use this account as their faculty fixture, including permissions.spec.ts, which asserts that revoking a capability from faculty yields a 403. Admin can never have capabilities revoked, so that suite passes without testing what it claims.
Fix Reset the membership to faculty in ABC Institution
F3 Medium
Fee structures readable by faculty and exams
The fees.structures capability is declared holders: [] — never delegable beyond admin — but the GET is guarded by REGISTRY, and faculty and exams both receive real rows. The POST beside it asserts the capability correctly.
Fix campus.routes.ts:732, :737
F4 Low
Merchant configuration readable beyond administrators
The route’s own docstring says "Administrators only", but the guard is REGISTRY. No credentials leak — the service returns configured_keys, the names of filled slots, never values — so the disclosure is the provider, its test-mode flag and which keys are set.
Fix campus.routes.ts:849
F5 Low
Teaching-load allocations have no role guard at all
The GET calls viewerOf(req), which requires only a session, then returns the tenant’s allocations unfiltered. Every role reaches it, including guardian and employer — looser than both the page guard and the POST beside it.
Fix campus.routes.ts:182
F6 Low
Placement drives readable by every role except the filtered one
PlacementService.drives() scopes its query for employer and for no other role, so students, guardians and the exams office receive the institution’s full drive list.
Fix career.routes.ts:468
F7 Low
"All question banks" back-link is dead
The bank detail page links to /onyx/banks, which has no index page. Next prefetches it, so the console errors on load and the click 404s. A link audit confirmed this is the only link into any of the six detail-only segments.
Fix onyx/banks/[id]/page.tsx:89
F8 Low
Score denominators fail minimum contrast
Ten of twelve pages scanned clean. Both failures are the same rule and the same element: the shared Score component renders its denominator at opacity-70 over a tinted band, dropping below AA. Every marks table in the product inherits it.
Fix components/onyx-ui.tsx:631
F10 Low
Examinations calendar renders a future sitting as past
An exam three days ahead displays as "3 days ago / sat Wed, Aug 26" under the heading "Examinations already sat". The branch fires on status === ’completed’ regardless of date, and Math.abs() then discards the sign. Publishing marks sets that status, so any paper marked before its sitting date lands here. relativeWhen() one file away already handles the case correctly.
Fix onyx/exams/page.tsx:65
F11 Low
A learner’s own results identify examinations by database ID
The Grades section — labelled "Your official record" — shows Exam #125. The Assessments section directly above shows the paper’s real title. marksFor() never joins onyx_exams. A guardian viewing the same mark sees the correct title, because the guardian service resolves it.
Fix results/page.tsx:270 and profile/page.tsx:242
F9 Housekeeping
Test-suite institutions live in production
authoring-college-mt5yk4vh (tenant 471) predates this run and is an E2E artefact. The credentials CSV listed five institutions that no longer existed; those rows were pruned during this engagement and the file is now accurate.
Fix Delete tenant 471 after confirming it holds nothing real
03

What held under attack

the load-bearing half of the report

A defect list read alone gives no sense of what survived. These are the properties that were actively attacked and did not give way.

Multi-tenant isolation

Object IDs harvested from each tenant as its own admin, then requested from the other tenant's session in both directions across courses, members, assessments, exams, programmes and jobs. 59 attempts → 0 leaks, all clean 404 (never 403)

Write authorization

Seven escalation writes from each of six low-privilege roles: create an admin, escalate own membership, create a course, delete a member, patch tenant settings, award a skill, publish the timetable. 42 attempts → 0 breaches · 89×403, 12×404, 1×422

Session security

Cookie flags, token visibility from JavaScript, signature tampering and sign-out. HttpOnly + Secure + SameSite=Lax · document.cookie empty · tampered and signed-out cookies both 401

Examination integrity

Proved by running a real paper: staff see the answer key, the candidate's own view of the same questions does not; drafts are invisible; results stay hidden until released. 4 of 4 confidentiality properties held

Guardian consent

The family view checked against the sharing flags on the child record. attendance and results shown · fees "Not shared" · coursework, messages, applications, support all "Never"

Runtime stability

Roughly 220 authenticated page loads across every role, both consoles and three institutions. 0 × 5xx · 0 unhandled exceptions · 0 error boundaries

Code Lab

A problem opened, a solution typed into the Monaco editor, run, submitted, then read back from the API. editor mounts · Run and Submit judge · submission persisted with score and status

Performance

Six administrator pages, cold navigation, Singapore region. TTFB 31–139 ms · load 615–1202 ms

05

Scope and limits

stated so the coverage is not over-read
  • F5 and F6 are confirmed in source, not in an observed payload. Neither demo tenant holds allocation or drive rows, so both endpoints returned empty arrays to roles that should not reach them. The missing guard is real; the size of the exposure is not.
  • Proctoring was exercised only as far as its queue. The invigilation console and the proctor queue respond, but no camera or screen-share session was driven.
  • Payments were not exercised. No gateway is configured in any tenant, so checkout, invoicing and reconciliation are untested beyond their authorization guards.
  • Load and concurrency were not tested. The timings are single-user cold navigations, not a benchmark.
  • The lifecycle covered one learner sitting one paper. Multi-attempt, second marking, moderation, anonymous marking and transcript issue were not driven.
  • Accessibility was automated only. axe on 12 pages; no keyboard-only or screen-reader walkthrough, and axe catches a minority of real barriers.
